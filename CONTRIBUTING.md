# Contributing

Use pull requests for focused changes. Rule additions must demonstrate that a name is tracking-specific, document false-positive risk, and include adversarial tests. Interface changes must preserve local-only processing, keyboard access, responsive behavior, and an explicit review step.

Run `npm test`, `npm run check`, and `npm run build` before opening a pull request. Do not include real private URLs, credentials, access tokens, or browsing data in issues or fixtures.

The maintainer reviews correctness, privacy, accessibility, rule precision, documentation, and scope before merging. Passing automation does not guarantee acceptance.
